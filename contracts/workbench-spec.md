\## 一、 产品定位与核心原则（严禁偏离）\
1\. \*\*产品定位\*\*：一套面向工业领域的 \*\*Agent Harness 指挥工作台与评测数据生产流水线\*\*，而非普通问答工具。界面气质必须对齐 \*\*Linear + Cursor + Dagster + LangSmith\*\* 的高信息密度工程工作台风格。\
2\. \*\*全中文专业命名\*\*：除明确的技术缩写（API、MCP、URL、JSON Schema、DFM、DRC、Pass@k）及品牌名外，所有界面导航、标题、按钮、状态标签必须统一使用规范的简体中文。\
3\. \*\*无孤立死页面\*\*：所有视图必须围绕当前选中的 \*\*「领域工作区（Domain Workspace）」\*\* 联动，任何数据表均需包含清晰的字段列、状态标签、数据血缘跳转以及带明确操作指引的空状态（Empty State）。\

\## 五、 后端架构与核心引擎硬性约束（不可偷懒用伪代码代替）\
\
1\. \*\*禁止使用 \`codex exec\` 解析 stdout！必须对接双向长连接协议\*\*：\
&#x20;  \* 后端需内置基于 \*\*\`codex app-server\`\*\*（通过 \`--stdio\` 或 \`--listen ws\://127.0.0.1:\<port>\` 启动 JSON-RPC 2.0 服务） 与 \*\*多厂商统一网关（LiteLLM / Provider Adapter）\*\* 的双模调度层。\
&#x20;  \* 运行 \`codex app-server generate-ts\` 生成强类型契约；完整实现 \`initialize\` -> \`initialized\` -> \`thread/start\` / \`thread/resume\` / \`thread/fork\` -> \`turn/start\` -> \`turn/interrupt\` 生命周期，并将服务器推送的 \`Approval\` 双向确认请求精准路由到前端 Inspector 的审批队列。\
&#x20;  \* 支持异构子代理路由：允许主控 Agent 通过调度器为不同子代理显式分配不同的模型 Endpoint 与独立工作目录/沙箱策略。\
\
2\. \*\*“绝不轻易早停”的穷尽采集状态机（Deterministic Frontier Engine）\*\*：\
&#x20;  \* \*\*绝对不能仅靠 System Prompt 让 LLM 不要停止\*\*。必须在后端持久化数据库（SQLite/Postgres）中维护状态机：\`CrawlFrontier（待抓取队列）\` 与 \`EntityDeduplication（实体指纹库）\`。\
&#x20;  \* 每个工艺节点定义 \*\*量化停止判据（Exhaustion Criteria）\*\*：\
&#x20;    \* 必须遍历预设的 7 类工业信源渠道；\
&#x20;    \* 只有当所有渠道均已完成多轮同义词/长尾词扩充检索，且\*\*连续 3 轮的“新增有效且未入库信源率（Novelty Rate）”低于 \`2%\`\*\*，同时队列中无待重试任务时，状态机才允许将该节点标记为“全网已穷尽”；若单轮子代理上下文接近阈值，由状态机自动归档结果并拉起全新上下文的接力子代理继续执行。\
\
3\. \*\*核心数据库 Schema 必须完整建模\*\*：\
&#x20;  \* \`domains\`（领域配置、默认导出 Override Schema）\
&#x20;  \* \`process_nodes\`（工艺图谱节点、上下游边、工种、覆盖率统计）\
&#x20;  \* \`crawl_frontier\`（URL/Query 任务队列、重试次数、Novelty 追踪）\
&#x20;  \* \`raw_sources\`（原始页面/仓库快照、解析文本、状态）\
&#x20;  \* \`verified_references\`（权威度评级、规范条款提取、原始附件存储路径）\
&#x20;  \* \`benchmark_tasks\`（难题定义、岗位频率/耗时/损失评估、绑定 Ref IDs）\
&#x20;  \* \`verifier_specs\`（L1\~L4 检查项 JSON、Docker 镜像名、反向测试样本结果）\
&#x20;  \* \`eval_runs\`（多档模型评测记录、Pass@k、各层报错分布、定级标签）\
&#x20;  \* \`global_settings\`（多 API Provider 配置、能力矩阵、全局默认输出 Schema）\
